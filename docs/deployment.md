# Deployment guide (free tier)

| Piece | Host | Notes |
|---|---|---|
| Database | Neon (project `parking-system`) | `production` branch for live, `dev` branch for local work |
| Backend API + Socket.io | Render web service `parking-backend` | Defined in `render.yaml`; runs migrations on every deploy |
| Operator / admin dashboard | Vercel | Root directory `apps/dashboard` |
| Driver app | Android APK (Flutter) | Built with the Render URL baked in |
| Uptime ping | UptimeRobot | Keeps the free Render instance awake |

## 1. Database (Neon)

1. In the Neon project, open **Connect**, choose the **production** branch, turn **Connection pooling off**, and copy the connection string. Prisma migrations do not work through the pooler.
2. Keep it private. It goes into Render only, never into the repo.

Migrations are applied automatically by Render's build (`npm run db:deploy`).

## 2. Backend (Render)

1. Render → **New → Blueprint** → pick this GitHub repo. Render reads `render.yaml` and creates `parking-backend` (region Singapore, same as Neon).
2. When asked for the `sync: false` values, set:
   - `DATABASE_URL`: the production connection string from step 1.
   - `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET`: **test mode** keys from Razorpay Dashboard → Account & Settings → API Keys.
   - `DASHBOARD_URL`: put `http://localhost:3000` for now; you replace it after step 3.
3. The three JWT secrets are generated by Render. Don't change them later, or every logged-in user is signed out.
4. Wait for the deploy to go **Live**, then check:
   ```
   Invoke-RestMethod https://<your-service>.onrender.com/health
   ```
   Expect `status: healthy` and `database: connected`.
5. Create the first admin and operator accounts and the demo facility. Run once from your PC, with the **production** connection string:
   ```
   $env:DATABASE_URL="<production url>"; $env:SEED_ADMIN_PASSWORD="<strong, 10+ chars>"; $env:SEED_OPERATOR_PASSWORD="<strong, 10+ chars>"; npm run db:seed --workspace=apps/backend; Remove-Item Env:DATABASE_URL, Env:SEED_ADMIN_PASSWORD, Env:SEED_OPERATOR_PASSWORD
   ```
   The seed never wipes data unless `SEED_RESET=true`, which it refuses in production. Re-running it is safe; it only changes passwords you pass.

## 3. Dashboard (Vercel)

1. Vercel → **Add New → Project** → import the repo.
2. **Root Directory**: `apps/dashboard`. Framework: Next.js (auto-detected).
3. Environment variable: `NEXT_PUBLIC_API_URL` = `https://<your-service>.onrender.com` (no trailing slash).
4. Deploy, and copy the production domain (e.g. `https://parking-dashboard.vercel.app`).
5. Back in Render, set `DASHBOARD_URL` to that domain (exact origin, no trailing slash) and save. Render redeploys.
   To also allow preview deployments, separate several origins with commas.
6. Open the dashboard and sign in as the admin, then the operator.

## 4. End-to-end check

```
.\scripts\e2e-live.ps1 -BaseUrl https://<your-service>.onrender.com
```

It asks for the operator and admin passwords and runs the 12-step lifecycle: register, login, vehicle, top-up, balance, facilities, entry, active session, exit, wallet debit, operator log, and the repeated exit not being charged.
Production has no simulated payments, so at step 4 it pauses: log in to the mobile app with the test account it prints and top up through Razorpay test checkout (UPI `success@razorpay`). Use `-SkipTopUp` to test the debt path instead.

## 5. Uptime monitor (UptimeRobot)

Free Render instances sleep after about 15 minutes without traffic, and the first request after that takes about a minute.

1. UptimeRobot → **New monitor** → HTTP(s), URL `https://<your-service>.onrender.com/health/live`, interval **5 minutes**.
   `/health/live` doesn't touch the database, so the pings don't keep Neon awake.
2. Optional: a second monitor on `/health` every 60 minutes, to be alerted if the database connection breaks.

The backend's debt worker also runs every 30 minutes and briefly wakes the database. That is expected; keep an eye on Neon's compute usage page during the first week.

## 6. Driver app (Android)

Windows needs Developer Mode on (Settings → System → For developers) to build Flutter apps with plugins.

```
cd apps/mobile
flutter build apk --release --dart-define=API_BASE_URL=https://<your-service>.onrender.com
```

Install `build/app/outputs/flutter-apk/app-release.apk` on a phone. Print the gate QR codes from the dashboard's **Admin** page and do one real entry and exit.

## Known limits

- **Autopay** is simulated (`apps/backend/src/services/autopay.ts`). Real recurring charges need Razorpay to enable recurring payments on the account. Until then, saving a payment method in production fails, so a driver who misses the 48-hour window is fined and suspended instead of being charged automatically.
- **Deactivated operators** can't log in again, but a token they already hold stays valid for up to 8 hours.
- The release APK is signed with the debug key; create a release keystore before publishing to the Play Store.
